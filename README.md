# 시니어 일상훈련 인지케어 웹앱

고령자(특히 경도인지장애·정상 고령층)를 위한 **일상생활 기반 인지훈련** 웰니스 웹앱입니다.
추상적인 "뇌게임"이 아니라 장보기·요리 같은 **실제 일상 과제를 게임화**해, 훈련 후에는
"오늘 실제로 해보기" 미션으로 앱 밖 행동까지 이어지도록 설계했습니다.

> **이 앱은 웰니스 서비스이며 의료기기가 아닙니다.**
> 이 앱은 건강한 생활습관을 돕는 웰니스 서비스이며, 의료적 진단·치료를 대체하지 않습니다.
> "치매 예방/치료/진단" 같은 의료 효과를 주장하지 않고, "두뇌 건강 습관" · "일상 능력 지키기" 같은
> 표현만 사용합니다. 이 원칙은 카피뿐 아니라 기능 설계(예: 적응형 난이도·기능 프로파일 점수)에도
> 그대로 반영되어 있습니다 — 자세한 내용은 [기능 프로파일 & 적응형 난이도](#기능-프로파일--적응형-난이도) 참고.

전체 제품 스펙과 마일스톤 계획은 [`SPEC.md`](./SPEC.md)에 있습니다.

---

## 실행하기

```bash
npm install
npm run dev       # 개발 서버 (기본 http://localhost:5173)
```

빌드 / 미리보기:

```bash
npm run build      # dist/ 에 프로덕션 빌드
npm run preview    # 빌드 결과를 로컬에서 미리보기
```

별도의 백엔드·계정·로그인이 없습니다. 모든 데이터는 브라우저의 `localStorage`에만 저장되며,
서버로 전송되는 정보는 전혀 없습니다. 처음 실행하면 지난 2주치 데모용 더미 기록이 자동으로
채워져(9장 참고), 훈련을 하지 않아도 가족 화면이 곧바로 의미 있게 보입니다.

## 기술 스택

| 영역 | 선택 |
|---|---|
| 프레임워크 | React 18 + Vite |
| 언어 | **JavaScript만 사용** (TypeScript 미사용) |
| 스타일 | Tailwind CSS v3.4 (고령자 접근성 토큰을 `tailwind.config.js`에 커스텀 정의) |
| 라우팅 | react-router-dom |
| 상태관리 | Zustand |
| 차트 | Recharts (기능 프로파일 시각화) |
| 저장소 | 브라우저 `localStorage`만 (서버 없음) |
| 음성 안내 | Web Speech API (`SpeechSynthesis`), 기본값 꺼짐 |

의도적으로 하지 않은 것: 백엔드/계정/로그인, 실제 지도 API, 결제, 드래그 앤 드롭, 다크모드,
3D 그래픽. 이유는 [`SPEC.md` 12장 비목표](./SPEC.md#12-비목표-하지-말-것) 참고.

- `localStorage`는 `src/lib/storage.js` 한 곳에서만 접근합니다. 다른 파일은 전부 `useAppStore`를
  통해서만 데이터를 읽고 씁니다.
- 클릭 가능한 요소는 항상 `<button>`입니다(`<div onClick>` 없음). 순서를 정하는 과제는 모두
  드래그 없이 "탭으로 하나씩 고르기" 방식입니다.

## 화면 구성

하단 큰 탭 3개(**홈 · 훈련 · 가족**)만 있는 단순한 구조입니다. 설정은 홈에서 진입합니다.

1. **온보딩** — 이름·나이대(선택)·글자크게·음성안내를 4단계로 입력. 로그인 없음.
2. **홈** — 오늘의 추천 훈련, 연속 사용일(스트릭), 오늘의 실생활 미션, 기능 프로파일 요약, 설정 진입.
3. **훈련** — 게임 카드 목록 (장보기·요리 순서 맞추기, 이후 마일스톤에서 길찾기·복약 추가 예정).
4. **훈련 플레이** — 게임별 화면. 흐름은 "안내 → 잠깐 보여주고 가림 → 탭으로 재현 → (상위 레벨) 응용 문제".
5. **결과** — 잘한 점을 먼저 보여주고, "오늘 실제로 해보기" 실행 브리지 미션을 제안.
6. **가족** — 같은 기기의 `localStorage`를 읽어 기능 프로파일 차트를 보여주는 보호자용 화면.
7. **설정** — 글자 크게, 음성 안내, 데이터 초기화, 웰니스 고지.

## 게임(훈련)

각 게임은 순수 로직(`*Logic.js`)과 화면(`.jsx`)을 분리해 두어, 게임 규칙만 따로 콘솔이나
스크립트에서 검증할 수 있습니다.

### 장보기 미션 (`games/Shopping.jsx`, `shoppingLogic.js`)
- **영역:** 작업기억(항상) + 계산(레벨 4 이상)
- 장바구니 목록을 잠깐 보여준 뒤 가리고, 가상 진열대에서 탭으로 담습니다. 담은 것은 다시 눌러
  뺄 수 있고 벌점이 없습니다.
- 목록은 **하드코딩하지 않고** `recipes.js`의 요리 재료에서 만듭니다 — 그래야 "오늘은 미역국을
  끓입니다" 같은 실생활 맥락이 생기고, 코스 모드(마일스톤 9)를 붙일 때도 수정이 필요 없습니다.
- 레벨 4~5에서는 계산대 단계가 추가되어 "○○원을 내면 잔돈은?" 문제를 2~3문항 풉니다(레벨 4는
  1,000원권 단위, 레벨 5는 10,000원권 단위라 더 어렵습니다). 문항이 여럿이라 정확도가 0%/100%
  둘로만 나오지 않습니다.
- 난이도 레버: 목록 길이 · 노출 시간 · 방해 품목 수 · 계산 문항 수/단위.

### 요리 순서 맞추기 (`games/Cooking.jsx`, `cookingLogic.js`)
- **영역:** 순서화(항상) + 실행기능(레벨 4 이상, 재료 계량 문제)
- 조리 순서를 잠깐 보여준 뒤 가리고, 뒤섞인 단계 카드를 **드래그 없이** "몇 번째로 할 일을
  고를지" 탭으로 하나씩 선택해 재현합니다. 잘못 골랐으면 그 항목을 눌러 그 순번부터 다시
  고를 수 있습니다.
- 레벨 4 이상에서는 "물 두 컵의 절반은?" 같은 재료 계량 문제가 2문항 추가됩니다.
- 한국적 소재(밥·미역국·김치찌개·잡채·불고기 등)로 구성된 `recipes.js` 더미 데이터를 장보기와
  공유합니다.
- 난이도 레버: 단계 수 · 노출 시간 · 방해 단계 수 · 계량 문항 포함 여부.

두 게임 모두 끝나면 결과 화면에서 "오늘 실제로 해보기" 실행 브리지 미션(예: "오늘 저녁에
미역국을 직접 만들어 가족과 나눠 먹기")을 제안하고, 담으면 홈의 오늘 미션 목록에 쌓입니다.

## 기능 프로파일 & 적응형 난이도

마일스톤 5에서 구현한, 이 앱의 "학습형" 핵심 로직입니다. **의료적 판정처럼 보이지 않게 하는
것이 기능 요구사항 그 자체**라는 점이 특징입니다.

### 적응형 난이도 — `lib/adaptive.js`
- 게임마다 레벨 1~5가 있고(`levels{}`), 성적에 따라 **조용히** 오르내립니다. 화면 어디에도
  "난이도를 낮췄습니다" 같은 문구나 레벨 숫자 자체를 노출하지 않습니다.
- **비대칭 규칙:** 올리는 건 신중하게(같은 영역에서 **연속 3세션** 정확도 85% 이상), 내리는 건
  상대적으로 빠르게(**연속 2세션** 정확도 50% 미만). 너무 어려운 과제가 주는 좌절감이 너무 쉬운
  과제가 주는 지루함보다 이탈로 이어지기 쉽다고 보고, 실패 경험이 쌓이는 쪽을 먼저 막습니다.
- 레벨이 바뀌면 그 뒤 세션부터 새 레벨 값으로 기록되므로, 스트릭 계산이 자동으로 초기화됩니다
  (별도 카운터를 저장하지 않습니다) — 레벨업 직후 곧바로 두 단계를 건너뛰지 않습니다.
- 한 게임에 영역이 둘이어도(예: 장보기의 작업기억+계산) 판의 난이도는 하나이므로, 그 게임이
  항상 만들어 내는 "대표 영역"(장보기=작업기억, 요리=순서화) 성적만 보고 조정합니다.

### 기능 프로파일 — `lib/profile.js`
- 영역별로 0~100점을 매겨 홈·가족 화면 차트의 축 하나를 이룹니다.
- **최근 세션에 더 큰 가중**을 주되, 달력상 며칠이 지났는지는 보지 않습니다 — 훈련을 며칠
  쉬었다가 돌아와도 그 자체로 점수가 깎이지 않습니다. 꾸준함은 스트릭·세션 수로 별도 표시합니다.
- 정확도만 보지 않고 **레벨을 반영**합니다(레벨 1의 100%가 레벨 5의 80%보다 높게 나오지
  않도록, 레벨마다 도달 가능한 점수 천장을 다르게 둡니다).
- **최소 3세션 미만인 영역은 점수를 만들지 않고** "아직 기록이 적어요"로만 표시합니다 — 1세션
  만에 100점이 뜨는 일이 없습니다.
- "정상/주의/저하" 같은 등급이나 신호등 색, 또래 비교는 쓰지 않습니다. 낮은 축은 "아직 덜
  해본 활동"으로만 표현합니다.

### 차트 — `components/ProfileChart.jsx`
- **실제 세션이 있는 영역만** 축으로 그립니다(영역 목록을 코드에 고정하지 않음) — 아직 없는
  게임의 영역이 0점 축으로 표시돼 "못한다"는 오해를 주지 않기 위해서입니다.
- 축 3개 이하는 막대 차트, 4개 이상은 레이더 차트로 자동 전환합니다.
- 점수는 차트뿐 아니라 항상 보이는 숫자 목록으로도 병기합니다(색만으로 정보를 전달하지 않기
  위해, 그리고 hover에 의존하지 않기 위해).
- "글자 크게"를 켜면 rem 기반 레이아웃은 저절로 커지지만 Recharts에 넘기는 폭·폰트 크기는
  숫자(px)라 자동으로 따라오지 않습니다. 이 폭 값을 계산하는 `scale`이 바뀔 때 차트를 강제로
  다시 그리게 해(`key={scale}`) 좁은 화면에서 잘리는 문제를 막습니다.

## 데이터 모델

모든 접근은 `src/lib/storage.js` 한 곳을 통합니다(`localStorage` 키: `cognitive-care.appState.v1`).
JSON이 깨지거나 저장이 실패해도 예외를 던지지 않고 조용히 초기 상태로 복구합니다.

```
UserProfile      { name, ageBand, largeText, voice, createdAt }
Session          { id, date, gameId, courseId, domain, level, score, accuracy, durationSec }
                   - gameId:   'shopping' | 'cooking' (이후 'wayfinding' | 'medication' 추가 예정)
                   - domain:   작업기억 · 계산 · 순서화 · 실행기능 (이후 전망기억 · 공간기억 추가 예정)
                   - courseId: 코스 플레이면 코스 id, 낱개 플레이면 null (코스 모드는 마일스톤 9)
RealWorldMission { id, date, text, done }
AppState         { schemaVersion, profile, sessions[], missions[], levels{} }
                   - levels: { [gameId]: number }  게임별 현재 난이도(1~5), lib/adaptive.js 가 조정
```

`schemaVersion`이 다르거나 저장된 것이 없으면 지난 2주치 데모 시드(`lib/seed.js`)를 채워, 가족
화면과 기능 프로파일이 처음부터 의미 있게 보이도록 합니다. 설정 화면에서 언제든 데이터를 완전히
초기화할 수 있습니다(되돌리기 전 확인 단계 포함).

## 접근성 원칙 (요약)

고령자 접근성이 이 앱의 최우선 설계 원칙입니다. 전체 내용은 [`SPEC.md` 3장](./SPEC.md#3-고령자-접근성-최우선-원칙--모든-화면에-적용) 참고.

- 본문 최소 20px · 버튼 24px · 제목 32px, 설정에서 "글자 크게"(1.25배) 토글 제공.
- 모든 버튼·선택지 최소 터치 영역 64px.
- WCAG AAA 지향 대비, 회색 위 회색 텍스트 금지.
- 하단 큰 탭 3개만, 깊은 메뉴 계층 없음. 한 화면에 한 가지 주요 행동.
- **드래그 앤 드롭 금지** — 순서를 정하는 과제는 전부 탭으로만 가능합니다.
- 클릭 가능한 요소는 반드시 `<button>`, hover에만 의존하는 정보 없음.
- 정답/오답은 색+아이콘(+음성 옵션 시 소리)으로 즉시, 실수해도 벌점 없이 격려 위주 카피.

## 이후 확장 아이디어

지금은 로컬 프로토타입이지만, 다음 방향으로 확장할 수 있도록 구조를 잡아 두었습니다.

- **백엔드 전환:** `src/lib/storage.js`가 유일한 저장소 접근 지점이므로, 이 파일의 구현만
  API 클라이언트로 교체하면 나머지 코드(스토어·화면·게임 로직)는 거의 그대로 유지됩니다.
- **계정·기기 간 동기화:** 지금은 "같은 기기의 `localStorage`를 가족 화면이 함께 읽는" 방식인데,
  서버가 생기면 보호자용 별도 로그인·초대 링크로 자연스럽게 확장할 수 있습니다.
- **DTx(디지털 치료기기)로의 전환:** 적응형 난이도(`lib/adaptive.js`)와 기능 프로파일
  (`lib/profile.js`)이 이미 "성적 → 난이도 조정 → 영역별 점수화" 파이프라인으로 분리돼 있어,
  임상적으로 검증된 알고리즘이나 규제 대응 로직으로 교체하기 쉬운 지점이 명확합니다. 다만 현재
  구현은 의도적으로 의료적 판정 언어를 배제했으므로, 실제 DTx 전환 시에는 웰니스 카피와
  규제 대상 카피를 분리하는 작업이 별도로 필요합니다.
- **게임 확장:** `games/gameCommon.js`(레벨 clamp·세션 레코드 생성)와 `lib/games.js`(메타데이터
  레지스트리) 덕분에 새 게임을 추가해도 홈 추천·훈련 목록·기능 프로파일 축이 자동으로 따라옵니다.
- **코스 모드:** 여러 게임을 하나의 이야기로 묶는 기능(마일스톤 9)을 위해, 게임 로직은 이미
  서로 독립적으로 설계되어 있습니다(장보기가 실패해도 요리 게임은 정상 진행하는 식).
